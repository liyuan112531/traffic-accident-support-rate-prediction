# Data directory

This directory specifies the data contract and ships a synthetic demonstration
dataset. It contains no study data.

## Contents

| Path | What it is |
|---|---|
| `schema/data_dictionary.csv` | One row per documented column: its name, type, description, role, encoding, whether the experts use it, whether the meta-learner uses it, whether it is observable before judgment, and whether it is safe for public release |
| `synthetic/synthetic_cases.csv` | 600 synthetic cases carrying all sixteen claim and award pairs, generated by `scripts/make_synthetic_data.py` |
| `synthetic/README.md` | How the synthetic dataset was built, and what it may and may not be used to claim |

## The data contract

A case table must be one row per case with paired columns

```
<item>_claim     the amount claimed for that head of loss
<item>_award     the amount awarded for that head of loss
```

for all sixteen items, plus a `case_id`. `claim_total`, `award_total`, `doc_year`,
`doc_region` and `doc_proc_level` are read when present; the two totals are
recomputed from the item columns if absent. The sixteen item identifiers are listed in
`data/schema/data_dictionary.csv` and in `src/preprocessing/schema.py`.

The loader validates the contract and fails loudly if a required column is missing,
if a case identifier repeats, if an amount is not finite, or if an amount is negative.
It never substitutes a default amount, because a defaulted amount would silently
become a fabricated observation.

## Fields that must not be used as predictors

Compensation items are decided together with attributes that are known only after the
judgment. Using any of them would leak the target:

- award amounts and anything derived from them;
- any support rate;
- the liability apportionment ratio;
- the disability grade;
- the number of heads of loss granted;
- properties of the judgment text, including its length.

`src/preprocessing/schema.FORBIDDEN_FEATURE_TOKENS` lists these and
`src/features/claim_features.assert_no_leakage` enforces the list on the request-side
block, so the rule is executable rather than advisory.

## Structural absence and behavioural zero

Two situations that a table cannot distinguish by looking at the award column alone:

- **`claim == 0`** — the item was never requested. No support rate exists. The value
  is `NaN` and the unit is excluded. This is *structural absence*.
- **`claim > 0`, `award == 0`** — the item was requested and refused. The support rate
  is `0.0` and the unit is a genuine observation with full weight. This is a
  *behavioural zero*.

Nothing is imputed at any point. `structural_absence_report` counts both per item so
that retention of the item universe can be inspected rather than assumed.

## The study dataset

Not here. The case-level dataset is not distributed, because the judgments it was
extracted from contain personally identifiable information and are not currently
publicly accessible from the original source. See
[`../docs/data_access.md`](../docs/data_access.md) and
[`../docs/privacy_and_data_policy.md`](../docs/privacy_and_data_policy.md).

## Regenerating the synthetic dataset

```bash
python scripts/make_synthetic_data.py                       # reproduces the shipped file
python scripts/make_synthetic_data.py --n-cases 2000 --seed 7
python scripts/make_data_dictionary.py                      # regenerates the dictionary
```

The default seed reproduces the committed file byte for byte, so the demonstration
output tables under `examples/synthetic_demo/expected_output/` stay valid. A different
seed produces a different dataset with the same structure, which is a useful check
that any conclusion you draw is not an artefact of one draw.
