## [1.0.0] - 2026-09-27

First public release. The repository is a method-level reference implementation,
not a redistribution of the study dataset.

### Added

- **Package `src`**, organised by stage:
  - `src/preprocessing` — the sixteen-item contract, schema validation, claim and
    award matrices, the item support rate with structural absence encoded as
    `NaN`, the long (case, item) frame and the temporal split.
  - `src/features` — the 33-column request-side block, the 16 item indicators, and
    the 73-dimensional meta representation assembled as `[A | B | C]` with block
    widths 11, 13 and 49.
  - `src/experts` — the declarative registry of the eleven experts with their
    pre-registered hyperparameters, and the item-wise simplex-constrained convex
    combination expert.
  - `src/meta_learning` — the item-balanced weighting scheme, the Item-Balanced L1
    objective with the smoothed mixture loss and its analytic gradient and hessian,
    and the selection routines.
  - `src/aggregation` — the claim-structure-driven aggregation and the conservation
    identity check.
  - `src/evaluation` — item-level, macro-averaged, cell-level and case-level
    metrics.
  - `src/statistics` — the case-stratified paired bootstrap, the paired permutation
    test and the Benjamini-Hochberg and Holm corrections.
  - `src/interpretation` — TreeSHAP attribution by block and the disagreement
    quartile table.
  - `src/utils` — path resolution, deterministic environment setup, shared CLI
    helpers and paired-comparison assembly.
  - `src/pipeline.py` — the single orchestration module that assembles the whole
    method so the executable scripts stay thin.
- **`scripts/`** — one executable stage per file: synthetic data generation, data
  dictionary generation, expert training, meta training, evaluation, bootstrap,
  permutation testing, interpretation, and an end-to-end demonstration that
  reports its own verification checks.
- **`config/`** — `experiment_config.yaml` with the protocol, the pre-registered
  hyperparameters, the meta-representation decomposition and the aggregation
  definition; `paths.example.yaml` as the documented template for local paths.
- **`data/schema/data_dictionary.csv`** — 131 rows, one per documented column,
  describing type, role, encoding and whether the column is visible before judgment. It
  covers the case-table columns, the full seventy-three-column meta representation and
  the target and aggregation quantities.
- **`data/synthetic/synthetic_cases.csv`** — a parametric synthetic dataset of 600
  cases with all sixteen claim and award columns, generated by
  `scripts/make_synthetic_data.py`. It is not derived from any real judgment and
  contains no case identifiers from the study dataset.
- **`tests/`** — unit tests for the aggregation layer, the item-balanced objective,
  the metrics, the schema and the feature-block dimensions, plus an end-to-end
  execution test of the whole pipeline on the synthetic dataset.
- **`examples/synthetic_demo/`** — a runnable demonstration with the expected output
  tables it produces.
- **`docs/`** — reproducibility, data access, model description, experimental
  protocol, and the privacy and data policy.
- **`audit/`** — the public-release checklist, the data-leakage scan, the path and
  secret scan, the source mapping, and the release summary.
- **`.github/workflows/tests.yml`** — continuous integration on every push and pull
  request, over the pinned environment.

### Fixed

Defects found by executing every stage script end to end before publication, rather
than by reading them.

- **`scripts/make_data_dictionary.py`** now documents the claim side of the meta
  representation in full: all thirty-three positional columns `claim_0` … `claim_32`,
  under those names, plus the sixteen item indicators. The committed dictionary had
  been written by an earlier version of the generator and listed descriptive aliases --
  `log1p_medical_claim`, `item_is_medical` -- that appear nowhere in the code, so
  thirty-two of the seventy-three meta columns could not be looked up by the name the
  code uses. The committed CSV has been regenerated and now has 131 rows.
- **`scripts/make_data_dictionary.py`** and **`scripts/make_synthetic_data.py`** report
  a directory passed to `--output` as an argument error with an actionable message.
  Their `--output` is a file path, unlike every stage script, and the mistake previously
  surfaced as a bare permission error from the write that followed.
- **`scripts/train_experts.py`** expands the request-side matrix to the case-item unit
  level before indexing it. That matrix has one row per case while the rows below are
  indexed per unit, so a run restricted to a subset of cases raised an index error.
- **`tests/test_cli_contract.py`** is new. Every script must import, answer `--help`,
  write where it says it writes, and agree with the committed dictionary and synthetic
  table byte for byte. Each of the defects above would have been caught by it.

### Documentation

- **Licence confirmed.** The project is released under the MIT License; the LICENSE
  file carries the standard text with the four copyright holders, and both it and the
  README state the licence as settled rather than pending.
- **Repository URL recorded** in the README, `CITATION.cff` (`repository-code`),
  `pyproject.toml` (`[project.urls]`), the documentation and the audit records. No DOI
  is asserted, because none has been assigned, and no ORCID identifier is listed,
  because none was supplied.
- **The two run configurations are now stated explicitly** in the README, the model
  description, the reproducibility notes and the demonstration README: the lightweight
  demonstration is 10 experts, 72-dimensional meta representation, TabPFN disabled; the
  full paper configuration is 11 experts, 73-dimensional, TabPFN enabled; and the
  empirical experiments reported in the manuscript use the full configuration. TabPFN
  weights are not distributed with the repository in either case.

### Notes on scope

- The empirical dataset is **not** distributed. The underlying court judgment
  documents contain personally identifiable information and are not currently
  publicly accessible from the original source.
- The synthetic dataset exists to demonstrate that the code executes. It was not
  used to produce any result reported in the manuscript, and no script in this
  repository regenerates a manuscript figure or table.
- Model weights and caches are not included in the repository.
